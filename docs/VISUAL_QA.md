## 1. الهوية البصرية المعتمدة (Design Tokens Audit)

تم فحص ومطابقة جميع الرموز البصرية لنمط **Future Lab — Mission Control**:
- **الخلفية العميقة (`--color-canvas-deep`):** `#15171B` (فحمي داكن).
- **الأسطح والبطاقات (`--color-surface-base`):** `#292D33` (رصاصي داكن).
- **الحدود الهندسية (`--color-border-default`):** `#565D66` (فولاذي رمادي).
- **اللون المميز للعلامة والنشاط (`--accent-orange`):** `#FF812C` (برتقالي تقني محسوب).
- **النصوص عالية التباين (`--text-primary`):** `#DCE1E7` (فضي فاتح).
- **معدل التباين المحسوب (Contrast Ratio):**
  - `#DCE1E7` على `#15171B`: **13.5:1** (يتجاوز متطلب WCAG AAA البالغ 7.0:1).
  - `#FF812C` على `#15171B`: **6.2:1** (يتجاوز متطلب WCAG AA البالغ 4.5:1).
  - `#DCE1E7` على `#292D33`: **9.2:1** (يتجاوز متطلب WCAG AAA).

## 2. فحص النفاذية وأبعاد اللمس والتفاعل (Accessibility & Interactive Targets)

- **أبعاد مساحات اللمس (`--touch-min-size`):** معرفة كـ `44px` في [tokens.css](../src/design-system/tokens.css) ومطبقة على جميع أزرار التنقل وعناصر الـ Toolbar وروابط الـ Sidebar ومنافذ الـ SVG.
- **التفاعل بالسحب والإفلات (Drag & Drop):** تحويل إحداثيات المؤشر بدقة عبر `svg.getScreenCTM().inverse()` مع تقييد الحركة بحدود مساحة العمل (`10 <= x <= 670`, `10 <= y <= 470`)، واستخدام `setPointerCapture` لتتبع ناعم ومستمر.
- **التنقل والتحكم بلوحة المفاتيح:**
  - تحريك المكون المحدد بأسهم الكيبورد (خطوة 10px عادية، و 30px مع زر Shift).
  - حذف المكون المحدد عبر زر `Delete` أو `Backspace` (مع حماية حقول الإدخال).
  - التراجع `Ctrl+Z` والإعادة `Ctrl+Y` أو `Ctrl+Shift+Z`.
  - إلغاء التحديد عبر زر `Escape`.
  - جميع منافذ التوصيل والأسلاك تحمل `tabindex="0"` و `aria-label` و `:focus-visible` متباين.
- **تفضيل تقليل الحركة (`prefers-reduced-motion`):** مطبق بصرامة في [animations.css](../src/design-system/animations.css) بتصفير مدة الحركة (`0.001ms !important`) وإيقاف نبض الصمام والأسلاك الحركية لذوي الحساسية الدهليزية.

## 3. مصفوفة نقاط التجاوب المستهدفة (Responsive Breakpoints Matrix)

| المقاس المستهدف | نوع الجهاز | التخطيط البرمجي المطبق | حالة الفحص الفعلي |
|---|---|---|---|
| **320px** | هاتف صغير جداً | قائمة سفلية/درج متراكب، عرض أحادي العمود، تمرير رأسي فقط بدون overflow أفقي | `CODE_VERIFIED / SCREENSHOT_NOT_RUN` |
| **360px** | هاتف قياسي | درج هاتف `280px` منزلق، أزرار لمس \(\ge 44\text{px}\)، شبكة أدوات مضغوطة | `CODE_VERIFIED / SCREENSHOT_NOT_RUN` |
| **390px** | هاتف حديث (iPhone/Pixel) | درج هاتف متراكب مع خلفية معتمة `backdrop-filter: blur(6px)` | `CODE_VERIFIED / SCREENSHOT_NOT_RUN` |
| **768px** | جهاز لوحي (Tablet) | طي تلقائي للشريط الجانبي، صفحة المختبر تعرض الأدوات أعلى اللوحة | `CODE_VERIFIED / SCREENSHOT_NOT_RUN` |
| **1024px** | لابتوب صغير | شريط جانبي موسع، 3 أعمدة متوازنة (أدوات + لوحة SVG + قراءات) | `CODE_VERIFIED / SCREENSHOT_NOT_RUN` |
| **1440px** | شاشة عريضة / Desktop | نمط Mission Control الكامل مع شريط جانبي قابل للطي لـ 68px لتوسيع مساحة الرسم | `CODE_VERIFIED / SCREENSHOT_NOT_RUN` |

> [!NOTE]
> **إقرار الأمان والبيئة:** الفحص البصري التلقائي تم بالتحقق البرمجي الدقيق من وسوم HTML وخصائص CSS ومحددات Media Queries واختبارات `tokens.test.js` و `lab-integration.test.js`. أما التقاط لقطات شاشة فعلية عبر متصفح حي (Headless Browser Screenshots) فسُجل كـ **`NOT RUN`** لتعذر تشغيل المتصفح الرأسي في بيئة Sandbox القياسية الصارمة دون خادم عرض، وامتناعاً تاماً عن اختلاق نتائج غير منفذة.

## 4. قائمة التحقق البصرية السريعة للمستخدم قبل التسليم (Manual Visual QA Checklist)

يستطيع المستخدم أو قائد الفريق التحقق المباشر من الواجهة في أقل من دقيقتين عبر فتح المتصفح باتباع الخطوات التالية:

- [ ] **1. وضوح الألوان والتباين (Color Harmony):**
  - التأكد من ظهور الخلفية الفحمية العميقة `#15171B` والأسطح الرصاصية الداكنة `#292D33`.
  - التحقق من تباين النصوص الفضية `#DCE1E7` والبرتقالي التقني `#FF812C` دون إجهاد بصري.
- [ ] **2. التنقل بين الصفحات الخمس (Navigation):**
  - النقر على روابط: الرئيسية، التجارب، المختبر، الدليل، وعن المشروع والتأكد من سلاسة الانتقال.
  - طي الشريط الجانبي وتوسيعه والتأكد من انزياح أيقونة السهم.
- [ ] **3. التجاوب مع شاشات الهواتف (Mobile Drawer):**
  - تصغير عرض المتصفح إلى أقل من `768px` أو فتح وضع محاكاة الهاتف (DevTools).
  - الضغط على زر القائمة المربعة أعلى الشاشة للتأكد من انزلاق الدرج الجانبي مع خلفية معتمة.
- [ ] **4. لوحة رسم المختبر والتفاعل (Lab Canvas):**
  - تحريك بطارية أو مقاومة بالسحب والتأكد من حركة الأسلاك بسلاسة ودون تقطيع.
  - النقر على المفتاح وملاحظة انطفاء الصمام وتغير شارة الحالة إلى «دائرة مفتوحة».
- [ ] **5. اختصارات لوحة المفاتيح:**
  - الضغط على زر `Tab` حتى الوصول إلى قطعة، وتحريكها بأسهم الكيبورد، وتجربة `Ctrl+Z` للتراجع.


## اختبار قبول النسخة المصححة — متابعة إلزامية

**Browser QA = NOT RUN** في بيئة الإصلاح (Chromium أعاد `ERR_BLOCKED_BY_ADMINISTRATOR`).

شغّل `python3 -m http.server 3000 --bind 127.0.0.1` ثم افتح `http://127.0.0.1:3000/` على جهاز الفريق. اختبر الصفحات الخمس والشريط الجانبي في 360/390/768/1440 بكسل، ثم جرّب الدائرة النموذجية (9.09mA)، فصل سلك، تبديل المفتاح، عكس توصيل LED عبر المقاومة، والتراجع والإعادة. سجل أي عيب مرئي قبل العرض النهائي. لا تستخدم `file://` لأن وحدات ES Modules قد تُحجب.
